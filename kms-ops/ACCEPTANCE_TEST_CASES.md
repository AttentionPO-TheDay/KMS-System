# KMS 系统验收测试用例

本版13个测试内容、34个测试用例。国产平台集成不列入本次用例。测试结果与结论按实际执行填写。

## 使用说明

- 使用专用测试节点A、B、C及其真实节点ID；不同节点使用各自原设备或独立浏览器配置，保持HTTPS地址不变，不清除本地密钥存储。
- 管理员通过“管理控制台”进入；验收台地址为同一服务器的/acceptance/。性能任务串行执行，不与其他压测同时运行。
- 新增节点按管理端实际表单填写ID、名称、IP、端口、类型及已创建的域。节点入口填写“已有节点ID”后点击“进入节点”；未初始化节点先完成初始化，已有本机材料不得重复覆盖。
- 建议顺序：先执行06-01配置域，再执行01-01初始化及02-01生成；执行09-01申请批准并备齐AB、AC、BC授权，再执行05项及06-02分发，补齐三对基础会话后执行03项，随后执行07、10项查询。
- 依赖同一材料的查询完成后再执行11项更新及12项回收。01-02闭环和09-02撤销放在相关业务测试之后，或使用独立节点。每次压测确认候选数据范围，不回收生产密钥。
- 三节点协商前，AB、AC、BC两两有授权及双方确认的未过期基础会话，各原浏览器保存所需会话材料。各组记录并复用实际keyId、版本、池ID、批次ID及会话ID，不用随机编号冒充关联数据。
- 截图不包含私钥、会话密钥明文、Cookie或访问令牌。界面名称和阶段推进仅作为业务联动检查；算法实现、安全性质及性能结论按相应检测证据判定。
- “抗量子攻击种类不少于3种”仍保留为验收材料要求：按验收方认可的分类提交至少3类不同攻击的检测或评审材料，注明受测版本、算法参数、方法、证据位置及结论；08-01的三类协议边界检查不替代该量化要求。论文与专题报告按任务书认可的路径另行归档。

## 01 无证书密钥全生命周期自动化管理测试

### 01-01 节点初始化及统一密钥登记

测试项目：节点初始化及统一密钥登记

测试目的：检查节点能完成本地初始化，平台登记与工作台统计统一，不把初始化密钥排除在生成总数之外。

前置条件：管理员已创建专用节点A；A尚未初始化；测试浏览器允许本地密钥存储；后端及生成服务可用。

测试流程：

1. 打开受控演示入口，在“已有节点ID”中填写A的实际ID，点击“进入节点”。
2. 在节点首次初始化页点击“开始初始化”，保持页面开启，等待各算法完成；不要连续重复点击。
3. 点击“进入工作台”，记录累计生成密钥和当前有效密钥数量。
4. 打开“密钥生成”和“版本历史”，查看已登记的算法、keyId、版本及状态；再回到工作台点击“刷新”。

预期结果：

1. 系统识别节点A，进入初始化页，显示本节点身份及待初始化状态。
2. 显示各套材料的初始化进展；完成后平台登记信息与本机材料状态可查询，不展示私钥明文。
3. 工作台包含初始化登记的密钥，数字与实际记录对应，不出现另行排除初始化数量的口径。
4. 各页面能对应到同一批真实keyId和版本；刷新不重复创建密钥、不重复计数。

### 01-02 生成、更新、回收的生命周期衔接

测试项目：生成、更新、回收的生命周期衔接

测试目的：检查同一测试密钥从生成到版本更新、回收的记录能够关联，并区分生成与更新的计数语义。

前置条件：A已初始化；使用可回收的专用测试密钥；具备生成、更新及回收权限。本用例安排在其他联动用例完成后执行，或使用独立节点；回收后若仍需同算法密钥，应重新生成并记录新keyId。

测试流程：

1. 在“密钥生成”选择SM2卡片，点击“生成新密钥”（尚无登记时为“生成并登记”），记录返回keyId和版本。
2. 进入“密钥更新”，在同一算法卡片核对keyId，点击“更新到 vN”按钮，其中N为页面提示的下一版本。
3. 打开“版本历史”，在“keyId”筛选框输入上述ID，核对生成和更新前后的记录。
4. 进入“密钥回收”，用“keyId”筛选找到当前版本，点击该行“回收”；原因填写“验收测试：生命周期闭环”，点击“确认回收”。
5. 刷新回收页、版本历史和工作台，核对状态、原因和数量变化。

预期结果：

1. 生成返回新的keyId，平台与本地登记可对应。（此处补充步骤1截图或检测记录）
2. 更新沿用该keyId，版本递增；显示自检及存证状态，存证失败不能当成上链成功。（此处补充步骤2截图或检测记录）
3. 同一keyId的版本演变可查询，历史记录没有被新版本抹去。（此处补充步骤3截图或检测记录）
4. 当前版本进入已回收状态，回收原因及处理结果显示；不可恢复的操作只影响所选测试密钥。（此处补充步骤4截图或检测记录）
5. 各页面状态一致；更新不增加独立密钥生成数，回收不新增密钥，审计或历史信息可追溯。（此处补充步骤5截图或检测记录）

## 02 分布式密钥生成测试

### 02-01 节点生成新密钥及本机自检

测试项目：节点生成新密钥及本机自检

测试目的：检查现有节点生成入口能够产生新keyId、登记公钥并提供本机材料一致性及自检结果。

前置条件：节点A处于可用状态，原设备材料齐全；生成签发服务可用；已有同算法密钥便于比较。

测试流程：

1. 进入A的“密钥生成”，记录Kyber／双份额KEM卡片当前keyId和版本。
2. 在该卡片参数下拉框选择“双份额 KEM v1 · 参数 768”，点击“生成新密钥”，等待返回结果。
3. 在同一卡片点击“自检”，等待本机检查完成。

预期结果：

1. 页面显示当前节点A；对应算法卡片及下方对照表显示已登记的keyId、版本和可用状态，卡片显示本机材料存在。
2. 成功结果具有不同于原记录的新keyId，参数对应768；按钮运行期间显示生成中，不重复提交。
3. 正常材料显示自检通过；失败时明确显示原因，不以登记成功替代自检成功。

### 02-02 密钥生成速率

测试项目：密钥生成速率

测试目的：核验任务书每秒生成不少于100000个密钥的量化指标。

前置条件：管理员身份；验收台“无证书密钥生成速率”执行器可用；已核实该场景使用的算法、环境及计数口径；使用独立验收数据，其他压测已结束。

测试流程：

1. 管理员打开/acceptance/，点击顶部“验收测试台”，找到“无证书密钥生成速率”卡片。
2. 核对卡片目标和证据来源，点击该卡片“执行项目”；此入口使用预设配置，不需要额外填写线程表单。
3. 等任务结束，点击“刷新看板”，在“执行结果看板”查看对应指标的实测值、状态、时间和说明。
4. 保存本次运行摘要及检测工具输出，核对实际生成数量、测量时长与算法；以实际生成数量除以测量时长计算速率。

预期结果：

1. 展示生成指标、目标值和执行器状态；不可用时如实提示，不能作为通过。（此处补充步骤1截图或检测记录）
2. 任务进入执行中状态，实际生成场景开始，不把点击按钮或请求发出数量作为生成结果。（此处补充步骤2截图或检测记录）
3. 看板显示本次实测结果，不沿用旧运行值；如存在错误则显示失败或需复核。（此处补充步骤3截图或检测记录）
4. 经核实的真实生成速率应≥100000个/秒；只有成功请求TPS但无法核对密钥数量时，保留待复核，不能直接判定生成性能通过。（此处补充步骤4截图或检测记录）

## 03 多节点贡献式密钥协商测试

### 03-01 三节点贡献、交换及全员确认

测试项目：三节点贡献、交换及全员确认

测试目的：检查A、B、C分别贡献随机材料，经过承诺、加密交换、共同派生与全员确认完成同一协商。

前置条件：三个节点在各自原浏览器设备上操作；AB、AC、BC两两基础会话已建立且双方确认；AB、AC、BC两两通信授权均有效，三个原浏览器均保存所需基础会话材料；基础会话均未过期。

测试流程：

1. 在A打开“会话管理”，点击“多方协商”标签，在参与节点下拉框选择B和C，点击“发起多方协商”，记录协商ID。
2. 在A、B、C各自页面点击“刷新”，找到同一协商ID，点击该行“查看”。
3. 三个节点分别点击“生成随机贡献并提交承诺”；每点击一方后记录进度，等待承诺达到3/3。
4. 三个节点分别点击“加密发送本节点贡献”，等待密文交换达到3/3。
5. 三个节点分别点击“校验贡献、派生密钥并确认”，观察1/3、2/3及3/3的确认进度。
6. 三方刷新同一协商详情，查看最终状态、本地保存提示及执行记录。

预期结果：

1. 新建独立协商记录，参与者为A、B、C，初始状态为等待贡献承诺。（此处补充步骤1截图或检测记录）
2. 三方看到同一协商ID和参与者集合，只能在自己的身份下提交材料。（此处补充步骤2截图或检测记录）
3. 承诺由各方独立提交；未满3/3时等待其他参与者，不提前进入已建立状态。（此处补充步骤3截图或检测记录）
4. 所有参与者发送后进入确认阶段；页面不展示贡献明文或通道密钥。（此处补充步骤4截图或检测记录）
5. 未全员确认时不显示已建立；3/3且确认一致后才完成协商。（此处补充步骤5截图或检测记录）
6. 显示“全员确认一致，协商已建立”，原设备显示共同派生密钥已加密保存；事件记录对应本次协商。本用例不将该功能称为安全多方计算的安全证明。（此处补充步骤6截图或检测记录）

### 03-02 未全员参与及关闭协商

测试项目：未全员参与及关闭协商

测试目的：检查部分节点未参与时不会假成功，关闭后不能继续推进。

前置条件：与03-01相同；新建一条专用协商，不关闭仍在使用的协商。

测试流程：

1. A选择B、C，点击“发起多方协商”，打开新协商详情。
2. 只在A和B点击“生成随机贡献并提交承诺”，C不操作；三方点击“刷新”。
3. 在A点击“关闭协商”，在出现的确认框中确认关闭。
4. B和C刷新该协商，再查看操作按钮及状态。

预期结果：

1. 产生新的独立协商ID，不覆盖之前已建立记录。（此处补充步骤1截图或检测记录）
2. 贡献承诺为2/3，保持等待状态，不出现密钥已建立或全员确认成功。（此处补充步骤2截图或检测记录）
3. 协商进入已关闭状态，保留参与者与关闭事件。（此处补充步骤3截图或检测记录）
4. 不再提供提交贡献或确认的可执行入口；在线页面清理本地该次协商状态，不影响旧的两节点基础会话。离线设备不据此认定已远程擦除。（此处补充步骤4截图或检测记录）

## 04 密钥生成攻击防御测试

### 04-01 伪造生成节点身份

测试项目：伪造生成节点身份

测试目的：检查生成签发入口不接受客户端伪造的节点身份。

前置条件：管理员可用验收台；“密钥生成协议校验”安全执行器可用；使用内置独立临时会话探针。

测试流程：

1. 在“验收测试台”找到“密钥生成协议校验”卡片。
2. 在“测试方式”下拉框选择“伪造生成节点身份”。
3. 点击“执行所选测试”，等待结束，点击“刷新看板”。
4. 保存该用例的本次摘要或请求证据，核对拒绝码及合法对照请求。 看板仅核对本组汇总状态、通过数量、证据来源和时间；单项请求、拒绝码及合法对照结果从本次检测脚本输出或运行日志留存，不在页面寻找独立明细按钮。

预期结果：

1. 卡片列出三种生成入口协议测试，显示实际执行器状态。（此处补充步骤1截图或检测记录）
2. 显示仅执行所选身份注入用例，不需要手工填写foreign-node或访问令牌。（此处补充步骤2截图或检测记录）
3. 用例返回本次真实结论；组内只执行一项时不能据此把整组3项写为全部通过。（此处补充步骤3截图或检测记录）
4. 注入身份应被拒绝，证据为INVALID_PARAMETER，合法节点读取仍正常；500、404和执行器未就绪不计为防御成功。 单项证据对应本次脚本输出；仅执行部分探针时，整组“需复核”不直接等于本项失败。

### 04-02 未授权算法替换

测试项目：未授权算法替换

测试目的：检查生成入口拒绝不允许的算法替换。

前置条件：同04-01，上一任务已结束。

测试流程：

1. 在“验收测试台”找到“密钥生成协议校验”卡片，在“测试方式”中选择“未授权算法替换”。
2. 点击“执行所选测试”，等待内置探针发送RSA-512替换请求。
3. 点击“刷新看板”，查看本次运行结论和证据。 看板仅核对本组汇总状态、通过数量、证据来源和时间；单项请求、拒绝码及合法对照结果从本次检测脚本输出或运行日志留存，不在页面寻找独立明细按钮。

预期结果：

1. 页面选择项与本次待测用例一致。（此处补充步骤1截图或检测记录）
2. 非白名单算法被明确拒绝，不登记该算法的业务密钥。（此处补充步骤2截图或检测记录）
3. 证据返回KEYGEN_SCHEME_INVALID，合法对照读取正常；记录本项结论，不用旧结果替代。 单项证据对应本次脚本输出；仅执行部分探针时，整组“需复核”不直接等于本项失败。

### 04-03 生成请求格式破坏

测试项目：生成请求格式破坏

测试目的：检查残缺JSON不会导致非法签发或服务器内部错误。

前置条件：同04-01；上一任务已结束。

测试流程：

1. 在“验收测试台”找到“密钥生成协议校验”卡片，在“测试方式”中选择“生成请求格式破坏”。
2. 点击“执行所选测试”，等待内置探针执行结束。
3. 点击“刷新看板”，核对本项及04-01、04-02的执行时间和结果。 看板仅核对本组汇总状态、通过数量、证据来源和时间；单项请求、拒绝码及合法对照结果从本次检测脚本输出或运行日志留存，不在页面寻找独立明细按钮。

预期结果：
