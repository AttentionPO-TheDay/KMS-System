# 预期结果表述（课题1 · 密钥全生命周期管理系统）

> 用途：测试文档「预期结果」页面，与截图一一对应。
> 句式参照：`4-1 数字身份创建成功，密钥全生命周期管理系统调用成功，DID服务调用成功，身份信息正确上链存储。`

## 句式约定

- 编号 + 若干**逗号分隔的断言分句**，末句落在"…正确上链存储。"
- 动词固定用 **成功 / 正确 / 一致**，不用"应该""正常了""没问题"这类模糊说法。
- 一条只讲**同一层**的事（界面层或接口层或链上层），不要把三层塞进一句。
- 每条都要**可自证**：截图里必须能看到可核验的标识（密钥ID、交易哈希、区块高度、时间、状态列）。

## 两个措辞上的提醒（评审会问）

1. **抗量子那条必须在句子里点明"演示模式"**，例如：
   > 4-x 抗量子密钥（演示模式）生成成功，密钥记录正确上链存储。
   代码里 CL-Kyber / CL-Falcon 走的是 `demo_generated`，严格无证书模式未实现
   （见 `doc/key-generation-test-description.md` 第 6 节）。写成"抗量子密钥生成成功"
   被追问实现方式时会很难解释；主动写明反而显得测得住。
2. **"上链存储"要能自证**：截图建议包含交易哈希 + 区块高度 + 查询时间三样。
   只截一张"已上链"标签，等于没有证据 —— 标签是前端写的，哈希是链给的。
