## 1. 功能定位

面向用户提供**无证书（certificateless）非对称密钥的在线生成与登记**能力：
用户在本机生成自己的密钥材料，系统（KGC）只签发**部分私钥**，
最终私钥在用户侧合成、**服务端无法单独恢复**；
生成记录经消息队列异步入库并**上链存证**，形成可核验的密钥生命周期起点。

支持的算法：

| 算法类型 | 算法名称 | 生成方式 | 是否上链 |
|---|---|---|---|
| 无证书非对称加密 | SM2 | 用户提交部分公钥 uA，KGC 签发部分私钥 | 是 |
| 无证书非对称加密 | SSCL | 同上，另附域参数（`keyDomain`） | 是 |
| 无证书非对称加密 | CL-Kyber / CL-Falcon | **演示模式**（`demo_generated`） | 是 |

## 2. 业务流程（测试步骤的主线）

```
① 用户登录用户前台 → 进入「密钥生成」
② 页面生成本地材料（本地公私钥对）        ← 私钥仅存在于浏览器/本地，不上传
③ 填写：算法名称 / 密钥名称 / 密钥用途 / 所属域 / 是否自动更新
④ 提交 → 浏览器把**用户部分公钥 uA**（SM2/SSCL）随请求发出
⑤ generate-go：按算法签发 KGC 部分私钥（SSCL 另含域参数）
⑥ 投递 Kafka `key_generate_log`（ENROLL_KEY）
⑦ generate-java 消费 → 写入 `kms.keymanage`（version=1、status=活跃、chain_status=待上链）
   并发起上链任务到 `key_chain_task`
⑧ 调用 FISCO 合约 `uploadKey(keyId, userName, pubKey, algo, usage, isAutoUpdate, version)`
⑨ 回写存证字段：`chain_status=已上链`、`chain_hash`、`block_height`；结果投 `key_chain_result`
⑩ 用户前台「生成历史」/ 管理端「密钥查询」可查；管理端「区块链存证」可见该笔交易
```

> **注意 ⑤ 与 ⑦⑧ 是异步的**：接口返回成功只代表"部分私钥已签发并投递"，
> 入库与上链是随后的异步过程。测试断言必须分两步（见第 5 节）。

## 3. 涉及模块与接口

| 层次 | 组件 | 说明 |
|---|---|---|
| 前端 | `/user/` → 密钥生成 | 生成本地材料、提交、展示本地结果摘要 |
| 入站层 | `generate-go` `/generate/request/ENROLL_KEY` | 内部鉴权（`X-Internal-Token`）+ 已认证身份（`X-Kms-User`，由 Java 侧写入） |
| 业务层 | `generate-java` | 消费 Kafka、批量入库、发起上链任务 |
| 消息 | Kafka `key_generate_log` → `key_chain_task` → `key_chain_result` | 生成事件 / 上链任务 / 上链结果 |
| 存证 | FISCO BCOS 合约 `KeyEvidence.uploadKey` | 事件 `UploadSuccess(keyId, version, status, timestamp)` |
| 网关 | `/generate-api/`、`/lifecycle-api/`（Nginx，端口 80） | 前端只经网关访问，不直连后端端口 |

**关键字段**：`encrytType` 仅接受「无证书非对称加密」；SM2/SSCL 必须携带合法的
`uA`（130 位十六进制、`04` 开头、**在 SM2 曲线上**）；抗量子算法不提交 `uA`。

## 4. 关键设计说明（可作为"功能特点"小节）

1. **部分私钥，而非完整私钥**：KGC 由主私钥 `KGC_MASTER_SECRET` 派生并只签发部分私钥；
   完整私钥 = 用户本地秘密 + 部分私钥，在用户侧合成。因此
   **服务端数据泄露不等于用户私钥泄露**——这是无证书方案相对 PKI/IBE 的核心优势。
2. **私钥不出服务端 ≠ 私钥不出用户**：用户本地材料只保留在当前页面，可导出为密钥文件
   用于后续解封分发的信封；服务端库中 `key_value` 存的是**部分私钥材料（JSON）**。
3. **主私钥版本化**：记录写入 `ms_key_id`（如 `ms_v2`）与 `algorithm_version`，
   轮换主私钥时旧版进退役集，**历史记录的公钥仍可复算**，上链存证不因轮换失效。
4. **上链存证**：每条密钥的生成、轮换、状态变更都落到同一条 FISCO 链上，
   合约对 `keyId` 做 `require(records[_keyId].keyId == 0, "key exists")` 防重复登记。
5. **算法可扩展**：算法类型/名称是数据字段而非硬编码分支，新增算法不需要改表结构。

## 5. 可观测判据（测试断言点）

| # | 观测面 | 期望 |
|---|---|---|
| 1 | 接口返回 | `code=200`，`data` 内含部分私钥材料（SSCL 为 `SSCLKey`/`SSCLEA`/`SSCLDomain`） |
| 2 | 数据库 | `kms.keymanage` 新增一行：`version=1`、`status='0'`（活跃）、`chain_status` 初始为待上链 |
| 3 | 数据库（异步后） | `chain_status='1'`、`chain_hash` 非空、`block_height > 0` |
| 4 | 数据库（溯源） | `ms_key_id`、`algorithm_version` 有值（证明可复算） |
| 5 | 消息 | 三个 topic 依次有该 `keyId` 的记录，无堆积 |
| 6 | 链上 | 块高递增；该笔交易含 `UploadSuccess` 事件，`keyId` 与库内一致 |
| 7 | 界面 | 用户前台「生成历史」出现该条；管理端「区块链存证」可见其 tx 哈希与块高 |
| 8 | 负例 | 非法 `uA`（不在曲线/长度不符）必须被拒；`encrytType` 非「无证书非对称加密」必须被拒 |

## 6. 已知边界（如实声明）

1. **抗量子算法当前为演示模式**：CL-Kyber / CL-Falcon 走 `demo_generated`
   （由演示后端为演示链路生成并返回材料或引用）；**严格无证书模式
   （`strict_certificateless`）需要用户/节点本地秘密材料，当前薄 API 未实现**，
   显式调用会返回"未实现"错误。因此这部分**只作为链路演示，不作为密码学强度结论**。
2. **算法类型仅一种**：当前只支持「无证书非对称加密」（无传统 PKI 证书模式）。
3. **上链为异步**：受 Kafka 与 SDK 懒初始化影响，生成后立即查询可能仍是"待上链"，
   断言需允许短暂延迟（建议轮询 10~30 秒）。
4. **主私钥不可丢**：`KGC_MASTER_SECRET` 及其退役集是历史记录可复算的前提，
   丢失即无法复算历史公钥（链上存证随之失去可验证性）。
