KMS PLATFORM ARCHITECTURE

密钥管理系统技术架构介绍图

该仓库当前已演进为“统一用户入口 + 多业务子系统 + 共享运维底座”的拆分式架构。 普通用户经由 kms-user 进入工作台，分别触达密钥生成、生命周期管理、分发管理与验收能力； 各核心业务再通过 Go 接入层、Java 业务层、Kafka 消息链路、MySQL/Redis 和 FISCO BCOS 区块链完成完整处理闭环。

6 当前有效模块：用户入口、生成、生命周期、分发、验收、运维编排
3 核心业务链路：生成、更新/回收、分发记录维护
2 主要双层后端形态：Go 高并发接入层 + Java 业务处理层
1 统一共享底座：Kafka、MySQL、Redis、Nginx、FISCO BCOS、脚本编排

共享基础设施层

Shared Ops Foundation

Nginx

统一路由入口，按 generate / lifecycle 等路径或域名规则进行前后端流量分发。

Kafka

承接高并发业务消息，解耦 Go 接入层与 Java 业务层，并隔离生成、更新、回收、上链任务。

MySQL + Redis

MySQL 存储业务记录、权限申请与分发数据；Redis 用于缓存、幂等与链路辅助控制。

FISCO BCOS

作为链上信任底座，存储公钥状态、回收状态与关键审计凭据，提升可追溯性与防篡改能力。

kms-ops

统一运维编排目录，集中管理 docker-compose、启动脚本、压测脚本、中间件与链上依赖。

核心业务链路

Three Main Flows

生成链路

用户或管理员发起生成请求 入口可来自 kms-user 聚合页或 kms-generate/front 专项页面。
Go 接入层处理高并发请求 接收 Register、ENROLL_KEY、comparam 等请求并写入 key_generate_log。
Java 业务层消费并执行业务落库 完成生成记录入库、审计日志写入，并投递链上任务。
区块链记录可信状态 由链同步消费者完成公钥或关键事件上链，实现后续可追溯查询。

生命周期链路

发起更新或回收 统一从生命周期入口提交，包含自动更新配置、审批流程等能力。
Go 层拆分消息管道 更新消息进入 key_update_log，回收消息进入 key_revoke_log。
Java 层执行轮换、回收与审批 由 UpdateKafkaConsumer、RevokeKafkaConsumer 等模块分工处理。
链上同步状态变更 生命周期事件最终同步到区块链，保证吊销、回收等状态可审计。

分发与验收链路

分发记录服务提供业务台账 通过 kms-distribute Java 后端维护分发详情、批量新增和状态查询。
验收系统触发压测与回归 kms-acceptance/backend 调用 wrk 与脚本，验证生成、更新、回收链路指标。
运维底座统一编排 所有服务与中间件由 kms-ops 统一启动、停止、联调与环境配置。
结果反哺架构治理 验收数据帮助判断 Kafka 拆分、Go/Java 解耦和链路扩展是否达标。

架构要点

Design Notes
统一入口 普通用户统一进入 kms-user，降低多系统切换成本。
高并发接入 Go 层负责请求吸收与消息投递，适合承载高吞吐链路。
业务解耦 Java 层专注业务规则、数据库、审计、审批和链上同步。
可信审计 区块链承担关键状态佐证，适合公钥状态和吊销记录留痕。
