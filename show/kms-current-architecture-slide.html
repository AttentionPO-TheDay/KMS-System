CURRENT KMS TECHNICAL ARCHITECTURE

密钥管理系统当前技术架构

系统以 kms-user 作为统一用户入口，向下连接密钥生成、生命周期管理、分发记录和验收压测能力。 核心业务采用 Go 接入层 + Kafka 消息层 + Java 业务层 的处理模式，并由 MySQL / Redis / Nginx / FISCO BCOS / kms-ops 共同支撑运行、审计与链上可信存证。

6 个模块 kms-user、kms-generate、kms-updatedel、kms-distribute、kms-acceptance、kms-ops
3 条核心链路 生成、更新/回收、分发记录/验收
4 类核心技术角色 统一入口、业务服务、消息中台、可信底座

1. 业务系统分层

System Layers

统一入口层

kms-user 提供工作台、生成、生命周期、分发、权限申请统一入口，面向普通用户聚合能力。

/workbench /generate /lifecycle /distribute

生成系统

kms-generate 负责注册、公参获取、密钥生成、生成结果查询、入库审计和上链任务。

Go 8081 Java 9081

生命周期系统

kms-updatedel 负责密钥更新、回收、自动更新配置、生命周期查询、权限申请与审批。

Go 8082 Java 9082

分发与验收

kms-distribute 维护分发记录；kms-acceptance 负责压测编排、指标汇总和验收历史。

Distribute 8083 wrk 验收

2. 核心处理链路

Core Flows
生成链路入口 客户端或门户发起 Register、ENROLL_KEY、comparam 等请求。
消息接入 Go 接入层写入 key_generate_log，承担高并发请求吸收。
业务处理 Java 消费生成消息，完成入库、审计和链上任务投递。
生命周期入口 发起 UPDATE_KEY、REVOKE_KEY、自动更新与权限审批相关操作。
消息拆分 更新写入 key_update_log，回收写入 key_revoke_log。
状态变更 Java 分别执行轮换、回收、审批、回退与生命周期查询逻辑。
分发与验收入口 分发记录查询维护，以及生成、更新、回收链路压测与结果采集。
运行验证 kms-acceptance/backend 调用 wrk 和脚本对链路吞吐与稳定性做验证。
结果沉淀 形成分发台账、验收历史与指标数据，用于交付与运行评估。

3. 技术底座

Infrastructure
Nginx 统一入口 负责前后端请求路由与服务分流，是各业务模块的统一访问入口。
Kafka 消息中台 将请求接入与业务处理解耦，当前核心 Topic 包括 key_generate_log、key_update_log、key_revoke_log、key_chain_task。
MySQL + Redis MySQL 保存业务记录、分发台账、权限申请与生命周期数据；Redis 提供缓存、幂等与辅助控制能力。
FISCO BCOS 区块链 承接关键公钥状态、回收状态和链上凭据，支撑可信审计与结果追溯。
kms-ops 运维编排 集中管理 Docker Compose、启动脚本、压测脚本、中间件与链上环境配置。

4. 架构特征

Highlights
统一门户聚合业务入口 用户从一个工作台进入多条业务链路，降低跨系统切换成本。
Go 承担高并发接入 更适合请求吸收、快速投递消息和承载高吞吐场景。
Java 承担业务规则与审计 负责权限校验、数据库操作、审批流程、生命周期控制和上链协同。
消息驱动解耦主流程 生成、更新、回收等链路通过独立 Topic 分流，便于扩展和隔离。
区块链增强可信性 将关键状态写入链上，为密钥状态管理提供可追溯、防篡改能力。
