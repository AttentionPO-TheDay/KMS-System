## 实现与配置

- 每事务最多 500 把；锁定归属正确的当前行后，生成新材料、归档旧版、更新当前行、写入审计记录和 `key_update_outbox`。任一步失败整批回滚。
- MySQL 8.0.21+ `JSON_TABLE` 使用固定 SQL 和一个批量参数，减少 SQL 解析与参数绑定；SM2 使用 Bouncy Castle 固定基点 comb 乘法，每次仍生成安全随机份额。
- Go Kafka 定时缓冲从 500 ms 缩短为 20 ms。状态接口批量只读元数据与指纹，验收最多六路并行读取。
- 后台证明每组最多 200 个批次共用事务，前台更新活跃时让出资源。持久化任务通过 Kafka ACK 后删除，失败保留重试。
- 新事件只保存一次规范 `keyList` 字段；读取旧事件时去除重复 `keys` 别名。链任务每段最多 200 把，并按 UTF-8 字节数递归拆分至 ≤768 KiB，兼容默认 1 MiB 消息上限；任何分段失败保留整条任务重试。
- Java 默认改为 2–4 GiB 堆、G1、8 个并行及 2 个并发 GC 线程，暂停目标 50 ms。InnoDB 缓冲池从 128 MiB 扩为 2 GiB，已在线生效并保存配置。`innodb_flush_log_at_trx_commit=1`、`sync_binlog=1` 保持不变。
- 新增幂等迁移 `kms-ops/mysql/init/58_key_update_outbox.sql`。
